# Generated pipeline workspace

`Age_trajectory/` is the default workspace for the maintained three-stage pipeline.
It contains inputs downloaded by the pipeline, intermediate objects, audit records,
expensive checkpoints, and final outputs. Except for this README, the directory is
ignored by Git.

Do not run files from this directory. Run the numbered commands under `scripts/` from
the repository root. To use another workspace, pass the same `--workspace PATH` to
all three stages.

## Directory ownership

```text
Age_trajectory/
├── data/
│   ├── raw/                         # Stage 01 GEO downloads
│   ├── interim/                     # Stage 01 sparse matrices/ordered identifiers
│   ├── metadata/                    # Stage 01 sample- and cell-level metadata
│   └── processed/                   # Stage 01 AnnData objects
├── logs/                            # Checksums and construction/run summaries
├── tables/                          # Sparse-conversion and QC audit tables
├── archive/legacy_notebook_outputs/ # Generated by superseded notebook workflows
└── results/figure1d_python/
    ├── seurat_input/                # Stage 02 sparse R input, when required
    ├── sct_samples/                 # Stage 03 per-sample resume objects on fresh runs
    ├── *.rds                        # Stage 03 integration/PCA/final checkpoints
    ├── GSE200164_umap_clusters.csv.gz
    └── figure1d_unsupervised_clusters.png
```

The active `sct_samples/` directory makes a fresh maintained integration resumable.
The similarly named
`archive/legacy_notebook_outputs/figure1d_python/sct_sample_checkpoints/` came from the
superseded notebook pipeline and is retained only for provenance.

## Safe cleanup rules

- Never remove checkpoints merely because they are large if integration might need to
  resume.
- A file ending in `.tmp` is an incomplete atomic write. Remove it only after verifying
  that the corresponding completed artifact exists.
- `seurat_input/` can be regenerated by Stage 02, but Stage 03 needs it when neither an
  integrated nor a post-PCA checkpoint is available.
- Logs, checksum JSON, manifests, mapping tables, and validation CSVs are small and
  should remain with the analysis for provenance.
- `archive/legacy_notebook_outputs/` is ignored, generated provenance. Nothing in the
  maintained scripts reads from it.
- Use a new `--workspace` instead of `--force` when you want an independent clean run.
